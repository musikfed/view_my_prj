02 / CODE-LEVEL AUDIT

Что происходит внутри.

Проверено по приложенным исходникам. В реферате описана предполагаемая двойная проверка целостности; ниже показано, какие части действительно вызываются в текущем коде.

РЕАЛИЗОВАНО

Парсинг и конкурентная передача

parse_prj() собирает блоки MLT/PRJ/FL. Затем для каждого файла asyncio.gather() запускает отдельный fl_deploy() для каждого хоста; SFTP создаёт каталоги, делает put() и chmod(0644).

ОГРАНИЧЕНИЕ В ТЕКУЩЕЙ ВЕРСИИ

Проверяется только первый хост

После параллельной передачи verify_deployed_files(block['hosts'][0], ...) запускается только на первом узле, если был хотя бы один успешный ответ передачи. Другие узлы остаются без вызова SHA-256.

ИМЕНА И ПУТИ НЕ СОВПАДАЮТ

Ошибка пути проверки

Для тестового .prj загрузка формирует /tmp/test_test, а проверка выполняет sha256sum 'test_test.txt' в удалённой рабочей директории. Это не один и тот же путь, поэтому показанная в реферате целостность в такой конфигурации не подтверждается.

ПРОВЕРКА И ПОЛИТИКА БЕЗОПАСНОСТИ

Самопроверка отключена

Функция verify_integrity() существует, но строка её вызова закомментирована. Установлено AutoAddPolicy() для неизвестных SSH-ключей; в цикле деплоя отсутствует ограничитель целевых директорий SAFE_PATHS.

03 / EXECUTION DESIGN

Как устроен процесс

Технологические этапы из исходной версии: от локального .prj до сетевой доставки и попытки контроля. При переносе на большее число хостов однофайловый цикл повторяется для каждого FL.

01 — INPUT

Определение задачи

MLT: задаёт хосты, PRJ: задаёт целевой путь, FL: список локальных файлов.

02 — FAN-OUT

Параллельная отправка

asyncio.gather распределяет одну операцию передачи файла сразу на все перечисленные SSH-хосты.

03 — TRANSPORT

SSH/SFTP

Соединение с SSH-ключом, рекурсивное создание каталогов, загрузка файла, выдача прав 0644.

04 — VALIDATE

Проверка целостности

Локальная SHA-256 и попытка удалённого sha256sum. В текущем коде проверка ограничена первым хостом и ошибочным путём.
