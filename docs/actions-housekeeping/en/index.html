PEGINELAB · GITHUB ACTIONS · ENGINEERING CASE STUDY

Keep the automation. Lose the clutter.

A centralized GitHub Actions housekeeping job. Every four hours it scans accessible repositories and prunes completed runs older than two days, including their logs and run artifacts. Active workflows and source code remain untouched.

How it works

A single controlling workflow lives in musikfed/muzikfed. When the ACTIONS_CLEANUP_TOKEN secret is available, it can inspect all repositories the token permits. Without that secret, cleanup remains restricted to the current repository.

What is removed — and what stays

Eligible for deletion

  • Completed runs last updated more than 48 hours ago.
  • Logs and artifacts attached to the deleted workflow runs.
  • GitHub Actions caches unused for more than 14 days.

Never touched by this cleanup job

  • Source code, Git commits, branches, tags, and releases.
  • Workflow definitions in .github/workflows/*.yml.
  • Queued or currently running jobs.

Implementation details

The job starts on cron: 23 */4 * * * (UTC), manually, or when the housekeeping files change. concurrency avoids overlapping cleanup jobs. Each invocation caps deletions at 800 objects.

schedule:
  - cron: '23 */4 * * *'
permissions:
  contents: read
  actions: write

Cross-repository access uses a fine-grained personal token granting Actions: Read and write and stored in GitHub Secrets. No token is published here. Manual runs support dry_run to preview changes safely.

OlderThanHours = 48
UnusedCacheDays = 14
MaxDeletes = 800
DryRun = true | false

Caveats and boundaries

GitHub may delay scheduled workflows. Large archives can take several sweeps to clear. Deleting a run also removes its attached artifacts, so valuable release assets should be stored separately. The 185 / 0 result proves cleanup in one repository; it does not certify a successful sweep of all repositories.
