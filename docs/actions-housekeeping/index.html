GitHub работает. История не захламляется.

Центральный уборщик задач GitHub Actions. Каждые четыре часа он проверяет доступные репозитории, удаляет завершённые запуски старше двух суток и освобождает историю от ненужных логов и артефактов. Рабочий код и сценарии CI остаются нетронутыми.

Схема работы

Один управляющий workflow размещён в musikfed/muzikfed. При наличии секрета ACTIONS_CLEANUP_TOKEN он может обойти все разрешённые репозитории владельца. Если секрет недоступен, уборка ограничена текущим репозиторием.

Что удаляется — и что защищено

Удаляется по правилам

  • Только завершённые запуски, у которых последнее обновление было более 48 часов назад.
  • Логи и артефакты удаляемого запуска — вместе с его историей.
  • Кеши Actions, к которым не обращались более 14 дней.

Никогда не удаляется уборщиком

  • Исходные файлы, Git-история, ветки, теги и релизы.
  • Файлы сценариев .github/workflows/*.yml.
  • Задания в очереди и во время выполнения.

Как это устроено

Работа запускается по cron: 23 */4 * * * (UTC), вручную либо при изменении самого уборщика. Встроенная защита concurrency не даёт запускать две уборки одновременно. За один проход удаляется не более 800 объектов.

schedule:
  - cron: '23 */4 * * *'
permissions:
  contents: read
  actions: write

Для всех репозиториев используется fine-grained token с правом Actions: Read and write, сохранённый в GitHub Secret. Сам секрет в публикации отсутствует. Для проверки доступен ручной dry_run — он показывает потенциальные удаления без изменения истории.

OlderThanHours = 48
UnusedCacheDays = 14
MaxDeletes = 800
DryRun = true | false

Условия и ограничения

Запуск по расписанию может задерживаться на стороне GitHub. При большом архиве обработка может растянуться на несколько запусков. Сохранённые в Actions артефакты удаляются вместе с запуском, поэтому ценные релизные файлы нужно публиковать отдельно. Цифры 185 / 0 относятся к подтверждённой уборке одного репозитория, а не ко всем репозиториям.
